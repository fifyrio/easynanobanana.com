# AI 效果页交付 SOP

适用：在 easynanobanana 已有图片或视频能力上增加效果页、用途页和页面集群。
来源：2026-09-16～17 宠物视频会话 `09b985e5-76d5-4e82-8317-b61e3c0cb831`。
历史结果：8 页 × 14 语言，素材上传完成，代码提交并推送为 `9385463`。这是工程交付证据，不是 SEO 排名或收入验证。

配套：[翻译 SOP](./I18N_TRANSLATION_SOP.md) · [素材 SOP](./AI_SHOWCASE_ASSETS_SOP.md)
现有架构说明：[AI Tool Page Development Guide](./AI_TOOL_PAGE_DEVELOPMENT_GUIDE.md)。旧指南中的路由、接口和计费示例应以当前代码为准。

## 1. 开工输入与成功标准

先写清以下内容，再实现：

| 输入 | 要明确的内容 |
|---|---|
| 页面目标 | 目标用户、关键词族、搜索意图、页面要完成的动作 |
| 参考实现 | 一个已经跑通的相似页面和对应 Experience、API、presets |
| 页面分工 | 路由、目标词、独立内容角度、工具页或画廊页、CTA 去向 |
| 业务边界 | 是否涉及登录、积分、支付、数据库；已有授权范围 |
| 交付范围 | 语言、预设、图片、演示视频、是否要求真实生成验收和部署 |

最低成功标准：页面内容与功能一致，主要交互可用，翻译无缺键，实际引用媒体可访问，类型检查和构建通过。代码提交、线上部署、搜索收录分别记录状态，不能互相替代。

历史关键词量、KD 和 SERP 只作为当时的研究记录。新任务重新核实地区、日期、口径和搜索结果；不要把“专页一定胜过首页”“多加 schema 就能提升排名”作为保证。同义词只有在意图或内容有实质区别时才拆页。

## 2. 先核对复用链路

视频参考：

- `src/lib/kie-api/kie-video-service.ts`
- `src/app/api/video/generate/route.ts`
- `src/app/api/video/callback/route.ts`
- `src/app/api/video/task-status/route.ts`
- `src/data/ai-pet-dance-presets.json`

检查鉴权、预设校验、扣费、任务提交、回调、轮询和失败退款。检查数据库 `effect_type` 的类型/约束，以及 RPC 是否接受新效果参数，再判断是否需要迁移；历史中的“无需迁移”不能替代当前核对。

优先新增预设和效果注册，复用现有链路。没有需求依据，不改积分默认值、生成成本、支付模块或相邻工具。

## 3. 实现最小闭环，再扩页面

1. 新增 presets，核对 ID、生成提示词、展示素材路径；需要声音的效果核对音频参数。
2. 在现有 API 注册效果；图片效果如果通用接口已能接收提示词，不额外建接口。
3. 先完成一个英文页面和完整交互，再增加同类页面。
4. 服务端 `page.tsx` 负责文案与 metadata；客户端 Experience 负责上传、生成、状态和结果操作。
5. 同类页面复用组件，通过 namespace/预设配置传入差异；不复制整份大组件，也不为一次性用途搭通用框架。

现成组件参考：

- 工具页：`src/components/pet-dance/PetVideoPage.tsx`、`src/components/AiPetDanceExperience.tsx`
- 画廊页：`src/components/pet-dance/PetEffectGalleryPage.tsx`
- metadata / 内链：`src/lib/pet-video/page-helpers.ts`

信息意图可先展示可播放成品，再引导到工具；工具意图优先让用户找到生成入口。画廊不等于对应效果已经有生成器，CTA 应准确说明目标能力。

历史的“演示视频 → 定格图 → 付费视频”漏斗是当时不改付费模块的方案。复用前检查当前余额与成本，并验证图片中间步骤是否真的帮助用户；不要默认它已证明能提高转化。

## 4. 补内容、入口和媒体

- 每页独立 H1、正文、用例与 FAQ，共享交互文案不等于共享整页 SEO 内容。
- 配置 canonical、hreflang、真实 OG 图片及尺寸。
- 在 `src/lib/nav-data.ts` 和 `public/sitemap.xml` 注册入口，配置相关页与上级页链接。
- 对照 canonical、sitemap、重定向检查主机名和语言前缀；发现全站不一致时单独记录，不顺手改全站。
- 结构化数据与可见内容、真实功能和媒体一致，不为凑数量添加，不编造评价。
- 按[翻译 SOP](./I18N_TRANSLATION_SOP.md)和[素材 SOP](./AI_SHOWCASE_ASSETS_SOP.md)完成其余交付。

## 5. 验收与交接

```bash
pnpm run type-check
pnpm run build
```

人工检查桌面与手机的上传、预设、登录提示、生成状态、结果预览、下载和分享。检查未登录、余额不足及失败反馈；涉及真实付费生成时在当前授权范围内执行，未执行就标明未验证。

检查页面源码中的主要内容、H1、canonical、hreflang、相关链接和 sitemap。生成接口行为有改动时，对对应行为补针对性验证；纯文档或文案修改无需新增实现镜像测试。

交接必须列出：改动文件、检查结果、媒体状态、未完成事项、提交与部署状态。提交前检查工作区，只暂存本次文件，遵循项目媒体入库惯例。历史中视频素材使用 R2，本地镜像未提交；不要据此排除其他类型页面需要入库的资源。
